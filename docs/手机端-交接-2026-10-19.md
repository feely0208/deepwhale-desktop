## 三、两个总病根（必须优先解决）

### A. 桌面重启 → 令牌失效 → 手机 401
- 现象：App 里「新建失败」「任务列表拿不到」；`curl .../mobile/api/health?token=<文件里的token>` → **401**。
- 原因链：App 重启 → 网关重建 → 手机界面手里的令牌不是当前那个。
- 已做：`mobile-gateway.json` 持久化 `{port, token, secret, pairCode, enabled}`；App 端 `saveToken`（配对成功时）**+ 刚修**「地址直连（URL 带 `?token=`）也解析并保存令牌」。
- **待做**：`enterWithToken` 现在是「直接打开保存的地址」，应改成「先试保存地址，2s 不通再试 `REMOTE_ORIGIN`」，彻底免扫码。

### B. 插件改动必须重启 DSH 才加载
- 现象：插件里加了 `/mobile/api/tasks`，`dsh-home/plugins/` 的副本里**有**，但运行中的 DSH 返回 **404** —— 因为插件在 DSH 启动时加载。
- 结论：**只要动了插件代码，就必须让用户重启一次桌面**。UI 改动可以热更（见下）。

## 八、踩过的坑（别重踩）

1. **多帧 zstd**：`session.v4.jsonl.zstd` 是多个 zstd 帧拼接（魔数在 0、155…）。Node `createZstdDecompress` 流到第二帧报 `Unknown frame descriptor`，Python `zstandard` 也只出第一帧 → **按魔数 `28 B5 2F FD` 切帧逐个解**（`zlib.zstdDecompressSync`）。
2. **WebView 缓存**：HTML 用 `?v=`/`&v=` 绕过了，但 **`app.js` 的版本号没改就一直是旧 JS** → 新功能全不生效，表现为"所有按钮都不能点"。
3. **Cloudflare 隧道有 AAAA**，手机 WebView 走 IPv6 超时 → **白屏**；渲染必须用 **IPv4-only 的自建中继**（`https://deepwhale.org.cn/_relay/t/<id>`，VPS 115.120.202.30:8790 + nginx `/_relay/` + systemd `deepwhale-relay`）。
4. **配对码过期/一次性** → 深链 403；要新码。
5. **`mobileSelection.val` 是嵌套的**（`{current:{model,reasoningEffort}, pending:null}`）→ 直接读 `sel.model` 是空。
6. **`pmset sleep 1`**（1 分钟就睡）→ 合盖出门手机必断；已加 `powerSaveBlocker`，但**合盖仍会断网**（物理限制，跟用户说清）。
7. **中文变量名 / 中文逻辑**：bash 里绝不用中文变量名；复杂逻辑用 Python。

## C. 桌面端三个根因（都在 src/main/mobile-panel.ts / mobile-gateway.ts）

1. `rememberEnabled(true)` **从来没被调用** → 点过「关闭」后 `enabled` 永远 false，重启不自动开。
2. 自动恢复只挂在「手机连接」菜单回调里 → 用户重启后不点菜单，网关就不开。现在
   `service.ensureReady()` 之后自动 `ensureMobileGatewayAutoStart()`。
3. 「换一个配对码」调 `gateway.rotate()` **连令牌一起换**，却只持久化 pairCode →
   状态文件留旧令牌，重启复用旧令牌 → 手机 401（真机实测：设备令牌 health=200、文件里令牌 401）。
   新增 `rotatePairCode()`（只换码不换令牌），面板改用它并顺手写回当前端口/令牌。
4. **自动启动时没有把配对码落盘** → 状态文件里是上一轮的码，与二维码/内存里的新码对不上（真机验收
   想"读文件自己配对"就被挡了）。现在 `startGatewayInternal` 成功时也 `rememberPairCode`，
   打包守卫会断言「文件里的码能真的换到令牌」。

> ⚠️ 旧状态文件里可能还是旧令牌：**升级后手机需要重新扫一次码**，之后就稳定了
> （新构建会持久化并复用同一个令牌；换配对码也不再踢设备）。

### 外出（公网中继）404 修复（2026-10-19 傍晚真机）
症状：手机在外面（4G）连上中继后，**会话列表 / 任务都报 404**（`会话列表拉取失败（404）`、`接口 404: /mobile/api/tasks`）。
根因：中继页面地址是 `https://deepwhale.org.cn/_relay/t/<id>/mobile/`，而接口路径写的是**绝对路径** `/mobile/api/*`；
`base()` 在同源时返回空串 → 浏览器解析成 `https://deepwhale.org.cn/mobile/api/*`，丢了 `/_relay/t/<id>` 前缀 → 中继 404。
修复：`base()` 同源时取「页面路径里 `/mobile/` 之前的前缀」→ `https://deepwhale.org.cn/_relay/t/<id>`；
并加了前缀模拟测试（本地把 UI 挂到 `/_relay/t/abc123/mobile/` 下，确认接口请求带前缀；Mac 侧直连中继
`/mobile/` 与 `/mobile/api/tasks` 均 200）。⚠️ 与「安卓测试占端口」无关：两个通道互不影响。

## E. 已知取舍 / 没做的

1. **审批"手机优先"只覆盖"手机正开着该会话"**：手机页面隐藏会主动断 SSE（省电 + 不让口袋里的手机
   霸占审批），此时桌面面板照常出现。若手机开着会话但人不在，桌面要等 60s 才出现面板。
2. **图片发送受模型能力限制**：纯文本模型（如 DeepSeek-V4-Pro）发图会被宿主拒
   （`session/attachment-invalid / MODEL_DOES_NOT_SUPPORT_IMAGES`）。
   现在**已做引导**：手机端识别这个错误码 → 提示「这个模型不支持图片输入，换一个支持图片的模型再发
   （附件已保留）」并**自动弹出模型选择面板**；待发送附件不清空，换完模型可直接重发。
   （仍没做的是"提前"在 chip/面板上标注哪些模型支持图片 —— 模型目录里没有 modality 字段，
   要等宿主暴露或用一次探测缓存，先不做。）
3. **附件没有"重发/编辑"**：失败后待发送附件保留，再点发送会重传（图片会重新压缩一次）。
4. **真机验证覆盖面**：附件发送链路在 Electron（同一套 WebView 前端）+ 真 DSH + 我们自己的网关上
   端到端验过；真机上的系统文件选择器/相机无法用 hdc 稳定点按，真机验收只做「列表/聊天(含图片附件)
   /轨迹/chips/附件面板」的截图，未在真机上真的挑一张相册照片发出去。
5. 旧 HAP 的「自动进入」是本次修的：`aboutToAppear` 里那段曾经误嵌在 `catch` 里。
