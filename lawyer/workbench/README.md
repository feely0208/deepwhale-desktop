# 法律模式 · 律师工作台（框架原型）

> 这是一个**将要放进 DSH agent 预设里的「法律模式」模块**的独立框架原型（先不写入 DSH）。
> 启动即自动切换到「律师工作台」。工作台内容参考本机 `案件管理系统.app`，UI 采用鸿蒙「沉浸光感 / 材质」风格，背景支持**跟随系统 / 浅色 / 深色**并可通过**图片 / 视频 / GIF** 更换壁纸。

---

## 0. 这个模块是什么

- **定位**：DSH（DeepSeek Harness）agent 预设中的一个「法律模式」模块。
- **行为**：模块启动后**自动切换至律师工作台**，工作台作为该模式下律师的主要操作界面。
- **形态（本阶段）**：独立可打开的原型页面，用于确认方向；确认后升级为工程化并接入 DSH。

## 2. 工作台内容（参考案件管理系统.app 领域模型）

从本机 `案件管理系统.app` 抽取的**模块导航**与**数据模型**：

**模块导航**（侧边栏）：仪表盘 · 案件管理 · 客户管理 · 合同管理 · 财务管理 · 日程管理 · 文书管理 · 报表中心 · 律师管理 · 系统设置 · 个人中心

**核心数据实体**（`server/src/database.js`）：

| 表 | 主要字段 |
|---|---|
| `cases` 案件 | case_no, title, type, plaintiff, defendant, third_party, court, judge, handling_lawyer, status, priority, filing_date, acceptance_date, closing_date, amount, case_notes |
| `clients` 客户 | name, phone, email, id_card, address, type, notes |
| `case_progress` 进展 | title, content, progress_date |
| `documents` 文书 | name, type, file_path, file_size, uploaded_at |
| `fees` 财务 | type(income/expense), amount, description, fee_date |
| `schedules` 日程 | title, content, schedule_time, type(court/…), completed |
| `lawyers` 律师 | name, phone, license_no, intern_license_no, bar_association, years_of_practice, specialty, education, title |
| `contracts` 合同 | contract_no, name, type, counterparty, signing_date, effective_date, expiry_date, amount, status |

仪表盘默认页已按下述统计/列表示例实现（数据为模拟）：进行中案件、本月新收、待收费用、本周开庭；案件进度；今日/待办日程；最新案件表格（含状态徽章、优先级、进度条）。

## 3. UI 特性

### 主题引擎（`js/theme.js`）
- 三态：`跟随系统` → `浅色` → `深色`（顶栏主题按钮循环切换）。
- 跟随系统时监听 `prefers-color-scheme` 自动同步；偏好存 `localStorage`。
- Token 化颜色（`css/base.css: :root` 与 `[data-theme=…]`），对齐 DSH 原生深浅色观感，主色取 `#4f8cff`。

### 壁纸引擎（`js/wallpapers.js`）
- 类型自动识别：`.jpg/.png` 图片、`.gif` 动图、`.mp4/.webm/.mov` 视频。
- 内置精选库 + 「选择本地文件」上传（图片 / GIF / 视频均支持，`objectURL` 渲染）。
- 分层：壁纸层 → 主题着色层 `#wallpaper-tint` → 可读性遮罩 `#wallpaper-dim`，保证任何壁纸下文字可读。

### 鸿蒙「沉浸光感 / 材质」组件（`css/components.css`）
- **发光按钮** `.btn-primary`：渐变 + 光晕，hover 时「光源跟手」（跟随鼠标的径向光斑）。
- **沉浸进度条** `.progress`：渐变填充 + 流动高光 + 辉光(环形版 `.progress--ring` 支持)。
- **统计卡片** `.stat-card`：上浮 + 描边辉光 + 跟手光源。
- 所有带 `.glow` 的元素都通过 JS 更新 `--mx/--my` 实现**光效光源跟手**。

## 5. 接入 DSH agent 预设的路线（确认方向后执行）

当前原型是**独立页面**。要变成 `agent 预设里的法律模式模块`，建议分三步：

1. **数据/行为层复用**：本原型的工作台导航、领域数据模型、主题/壁纸引擎可直接移植进 DSH。
2. **接 DSH 客户端插件**（client-plugin）：利用 `@deepseek-ai/dsh-client-ui-agent-preset` 的注入机制，在工作台就绪后 `dispatch` 事件驱动 DSH 显示该工作台（对应「启动自动切换」）。
3. **壁纸与主题**：主题直接复用 DSH 的深浅色/跟随系统设置；壁纸作为工作台层，可选接本地资源路径。
4. 后续可把工作台各模块的状态（案件/客户/日程等）接到真实后端（参考 `案件管理系统.app` 的 `/api/*` 路由与 SQLite 表结构）。

- **新建授权申请**：从案件选择生成，自动带出 案号 / 案件名称 / 案由 / 当事人 / 法院 / 承办律师（= 被授权人/主办），并填写**申请事项**（委托代理/合作办案/费用审批/权限设置）与**核心内容**。
- **生成审批单（PDF 页面）**：一份「案件授权 / 签批申请单」，含 案号、案由类型、当事人、受托法院、申请事项、申请人(被授权人)、授权人、申请日期、核心内容 —— 可「**导出 PDF**」（`window.print()` 打印为 PDF，@media print 只输出审批单）。
- **授权人电子签**：审批单上手写签字板（鼠标/触屏绘制），可清除；「确认签批」后记录签名+签字人+签批时间，状态转「已签批」。
- **双方留档**：签批后记录写入 `localStorage`，以「已签批」状态分别留存授权人与被授权人工作台（列表含"申请人(被授权人)/授权人"两列）；支持「拒绝」。

- **拒签补充重发起**：授权人拒签时须填**拒签原因**；被拒后申请人可「补充材料并重新发起」（上传图片/PDF/视频/录音 + 说明），状态回到待签批；保留**流转记录**（发起/补充/拒绝/签批）。
- **签批方式双选**：**电子签**（手写板）与**纸质签批**（打印审批单→授权人纸质签字→上传扫描件回档，规避模仿/盗签风险）；记录带「电子签/纸质签」标识。
- **删除保护**：仅**从未进入签批流程、无任何签批结果/反馈**的申请（纯新建待签）可删除，且弹**二次确认**；已进入签批/有拒签或已签批反馈的显示 🔒 且不可删除（避免误删有流程痕迹的记录）。
